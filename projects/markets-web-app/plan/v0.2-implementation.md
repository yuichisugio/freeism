# Markets Web App v0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `markets.freeism.app` を商材の出品と Auction だけを担う独立した Cloudflare Workers アプリとして空の D1 から構築し、Google 認証、Points 明示連携、multi-unit uniform-price Auction、Hibernate WebSocket、全 winner 原子精算、proof／review／履歴 UI を承認済み v0.2 仕様どおり提供する。

**Architecture:** 親計画が作る TanStack Start の静的SPA shell + 4固定route prerender、Hono、Workers Static Assets の上へ、Markets 専用 Better Auth／Drizzle D1、Auction ごとの `AuctionRoom` Durable Object、D1 outbox を正本とする `AuctionSettlementWorkflow` を追加する。browser mutation は同一 origin Hono API から `AuctionRoom` へ送り、WebSocket は購読専用にする。Points とは `POINTS_SERVICE` Service Binding を transport にし、`points-worker` 所有 OpenAPIから生成した clientと、grant／scopeを分離したOAuth bearer tokenだけで連携する。

**Tech Stack:** Node `24.18.0`、pnpm `10.33.3`、Vite Plus `0.2.4`、TanStack Start `1.168.27`、React `19.2.7`、Hono `4.12.29`、Better Auth `1.7.0-rc.1`（開発・staging限定）、Drizzle ORM `0.45.2`、Drizzle Kit `0.31.10`、Cloudflare Workers／Static Assets／D1／Durable Objects／Workflows、Wrangler `4.110.0`、Vitest `4.1.10`、Workers Vitest pool `0.18.4`、`@playwright/test` `1.61.1`。

- MarketsはGoogleだけをlogin画面と明示Social Account Linking画面の両方へ表示する。Provider別の独自sign-in拒否hook、email/password、Apple、GitHub、email一致implicit linkを追加しない。本人識別は`providerId + accountId`だけで行う（DEC-048、DEC-051、DEC-053〜DEC-057）。
- MarketsとPointsはD1、Better Auth schema／secret、host-only Cookie、user ID、domain型を共有しない。MarketsからPointsのsource、D1 schema、Hono RPC型をimportせず、Points所有OpenAPIの生成型だけを使用する（DEC-019、DEC-020、DEC-087〜DEC-097）。
- 1環境につき1つのMarkets OAuth Client IDへ`authorization_code`／`refresh_token`／`client_credentials`を設定し、token class、scope、audienceを分離する。user tokenはbalance read／reservation create、M2M tokenはPackage listing eligibilityと、同じclientが作ったreservationのstatus／capture／releaseだけに使う（DEC-089〜DEC-096、DEC-256）。
- browserへPoints Access／Refresh Token、Client Credentials Token、Client Secretを返さない。user tokenはMarkets D1へversioned AES-GCM envelopeで暗号化し、refresh rotationはD1 lease／CASでsingle-flight化する。401後のrefreshと同一request再試行は各1回だけとする。
- link／unlink／relinkの`returnTo`はqueryなしの固定`/settings/points-connection`、Settlement retryはstate-boundかつqueryなしの固定`/settlements/{settlementId}`とする。caller指定interfaceを作らず、query、fragment、credential、別host、`//`、raw／encoded backslash、control文字、double-decode入力を拒否し、callback queryの遷移先を信用しない。
- Markets D1がlisting、Auction、bid、settlement、proofの唯一の永続Source of Truthである。DO memory、WebSocket attachment、Workflow stateを正本にしない（DEC-127、DEC-128、DEC-163、DEC-172）。
- `src/generated/points-markets-api.ts`はPoints所有OpenAPIから親contract commandだけが再生成する。Markets taskではVerify/Consume onlyとし、手編集、部分patch、`git add`対象への個別列挙を禁止する。
- price／quantity／sequence／versionはD1 `INTEGER`とJavaScript safe integerを使う。小数JSON number、D1 `REAL`、client時刻によるorderingを経済計算へ使用しない。Points component vectorをMarketsで正本化せず、settlementでは`pointPackageRevisionId`、`priceTicks`、`quantity`をPointsへ渡す（DEC-109、DEC-131、DEC-167）。
- listingと最初のAuctionはCSV 1行から同時作成する。UTF-8、5MiB、1,000非空行、server再parse、server draftなし、全件成功または0件、`Idempotency-Key`＋canonical payload hashを守る（DEC-114、DEC-115、DEC-118、DEC-129、DEC-225）。
- WebSocketはread-only subscription、bidは認証済みHTTP mutationとする。query token禁止、frame 4KiB、user×Auction 3接続、user全体20接続、heartbeatなし、`auctionVersion`／`bidSeq` gap時HTTP resyncを固定する（DEC-149〜DEC-152）。
- Auction終了処理は同じcutoff snapshotからのみ再計算する。確定的な残高不足者だけを1回blacklistし、一時障害で候補を除外しない。全winner・全axis captureはPointsの1 D1 transactionへ1requestで送り、capture後にrelease、refund、別winner再計算を行わない（DEC-144、DEC-164〜DEC-173）。
- capture前のPoints残高再検査で不足した場合は、M2M Problem Detailsの`insufficientReservationIds`をcurrent roundへ照合し、該当userだけを除外、旧ACTIVE reservationを全releaseし、同じcutoffから再計算する。IDはbrowser／public response／logへ出さない。0 tick winnerは0 vector reservationを`ACTIVE -> CAPTURED`へ進め、receiptを残すがledger／残高を変更しない。
- 通常successは`{ data, meta }`、errorはRFC 9457 `application/problem+json`＋安定した`SCREAMING_SNAKE_CASE` codeとする。private responseは`Cache-Control: private, no-store`、immutable public proofはcontent hash付きpublic cacheとする（DEC-158、DEC-197）。
- 直接dependencyは親計画のexact versionを使い、`^`、`~`、`latest`を追加しない。Better Auth `1.7.0-rc.1`は開発・staging限定で、productionは親計画Task 11の`1.7.0`正式版bumpと認証回帰成功まで失敗させる（DEC-085、DEC-086、DEC-200、DEC-201）。
- D1 migrationはDrizzle Kitで`0000`から生成し、schema source、SQL、snapshotを同じcommitへ入れる。`drizzle-kit push`、down migration、旧Prisma migration移植を使わない（DEC-006、DEC-187）。
- Workers integration testは毎suiteで空D1へ全migrationを適用する。実Google／Points credentialをfixtureへ置かず、OAuth／Service Bindingは署名済みfixtureとfetch stubで再現する。
- 親shellの`check`、`test`、`test:worker`、`build:staging`、`build:production`、`build:assert`を維持する。本計画で`db:generate`、`db:migrate:local`、`test:e2e`を追加し、Task 17で親contractの`db:migrate:staging`、`db:migrate:production`、`deploy:staging`、`deploy:production`、`smoke:staging`、`smoke:production`を具体実装する。
- `CLOUDFLARE_ENV=staging|production`はbuild時に選択し、flatten済み設定を直後にdeployする。`wrangler deploy --env`だけで既存buildを別環境へ切り替えない。production deployは親計画の`main` push pipelineだけが行う（DEC-175、DEC-181、DEC-182）。
