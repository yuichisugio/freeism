2. **指定ユーザーが設定する公式パッケージのデータを取得するパブリックAPI**

3. **逆オークション**
   - v0.2.1で実装しない理由
     1. 無料主義を説明する上で必須ではない
     2. 必要性はありそうなので、あとから実装する
   - 必要な理由
     - 無料主義の評価軸ポイントを使用した逆オークションを実施できる場がない
     - 多くのプラットフォームは既存通貨を対象としていて、気軽にいろいろなポイントを使用した逆オークションの場がない
   - 説明
     - 需要者が支払う事前の固定報酬額を決めるために、供給者が報酬を下げる方向で争う逆オークションする
     - 買い手がオークションを作成して、供給側が報酬額を下げていくオークション
     - 供給側の報酬を得る方法
       1. 買い手からの落札額のポイント譲渡
       2. 供給側の行為による評価軸からの評価による成果報酬
4. **市場を作る機能**
   - v0.2.1で実装しない理由
     1. 無料主義を機能させるうえで全く不要な機能
   - 説明
     - **需要側が支払う事前の固定報酬額は、供給者が受託まで報酬を徐々に高める機能**
     - オークションではなく、市場を作っている
   - 実装は不要な理由
     - 評価軸コミュニティ内で、時間単位ごとに報酬を増加して貢献度を評価するルールで運用すれば良いだけ。
     - 無料主義アプリに実装する必要は全くない
   - 使用例
     - React管理者がIssue作成時に自動で↑設定を行い、解決した人に報酬を付与する。
     - **無料主義アプリの機能としては不要だが、評価の方法としては有用**
     - 無料主義では受益者負担がないから、無尽蔵に報酬を増やせるので↑選択を取りやすい。でも、インフレしすぎるかも。
5. **事前の固定報酬を市場で決める仕組み**
   - v0.2.1で実装しない理由
     1. 無料主義を説明する上で必須ではない
     2. 一旦は、評価軸コミュニティ内でスプレッドシート管理で対応できそう
   - 説明
     - 各タスクに賞金をかける仕組み
     - その賞金は時間がたつほど徐々に報酬額が上がる
   - 使用場面
     - OSSのIssueの質問回答タスク
     - 15分ごとに一単位づつ報酬が増加する
   - 流れ
     1. （需要側）賞金タスクを作成
        - 作成時に、「タスク名」、「タスク内容説明」、「完了判定方法」、「初期の報酬額」、「一単位の増加時間」、「一単位の増加報酬額」、「提出可能人数」を設定
        - 例）「提出可能人数」は、ごみ拾いなど、何人でもよい場合は複数人設定で可能
     2. （供給側）タスク内容を確認して、タスク完了報告
        - 「提出可能人数」まで先着順で締め切る
     3. （需要側）完了を需要側が確認・承認して、賞金を確定
        - 完了報告ではなく、需要側による完了報告のチェックまで賞金は増え続ける。
          - それにより、早く完了報告の内容をチェックするインセンティブにしたい。
     4. （需要側）完了チェックした人に報酬を自動で付与
   - 工夫
     1. パブリックAPI経由で、タスクを作成できるようにしたい
        - GitHub内OSSでIssueが作成されたら自動で無料主義アプリの賞金タスクが作成されるフローを作成したい

7. **格差是正の仕組み（枠）**
   - v0.2.1で実装しない理由
     1. 無料主義を説明する上で必須ではない
     2. 必要性はありそうなので、あとから実装する
   - 説明
     1. 平方根にする方式
        - 保有ポイントが2500ポイントなら50ポイントだけ使用できる
     2. 当選率を使用する方式
        - 消費額や入札額を預けるのではなく、商材の応募率も掛け合わせた数を預ける仕組みにする？
        - **(1+(1-当選率))×入札額=得るために必要なポイント額**
          - 当選率が10%で購入額が500ポイントの場合は、1.9×500=950ポイント消費する

10. **共同所有自己申告税COST**
    - v0.2.1で実装しない理由
      1. 無料主義を説明する上で必須ではない
      2. 資産を登録する方法や実装が大変
    - 「共同所有自己申告税COST」の説明
      - 所有財産に一定の税率を掛け算した額を納税する
      - その人より多くの財産価値を提示した人に、強制的に引き渡す仕組み
      - 財産はブロックチェーンに登録して、上回る提示額の人にスマートコントラクトで自動で所有権が引き渡されるようにする
    - COSTの無料主義版として、自分が所有する財産価値の分のポイントを預ける。預けたポイントより多く預ける人がいたら、他に引き渡す必要がある仕組みでも良さそう

13. **条件付き代理購入する仕組み（権利を提供する側の人に戻ってくる）の機能**
    - v0.2.1で実装しない理由
      - 本質的ではなく、必須ではなく、必要になったらあとで実装で大丈夫そうなため
      - レバレッジを利かす機能は、一旦は「譲渡可能なポイント」機能で借金する仕組みのみで良さそう
        - 借金額の返済管理自体は、各評価軸の無料主義アプリの外で管理してもらう
      - **本項の「借金」と下記17項（借入・返済の管理）の関係**
        - 本項の「借金」は、**下記17項のようにアプリ内に借入枠・返済スケジュールの台帳を持つ機能**を指すものではない。v0.2.1は**譲渡可能なポイントの移動**に留め、返済の記録・督促は**各評価軸の運用（アプリ外）**に委ねる。17項は、そうした本格の借入管理をv0.2.1のスコープから外すための節である。
    - 機能説明
      - レバレッジを利かす機能
      - 付与したら、その人が使用した時に戻ってくる期間が決まる
