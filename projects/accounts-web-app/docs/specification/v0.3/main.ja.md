## v0.3で追加する機能

1. アカウントのID
2. 認証する
   1. OAuth認証
   2. bi-directional link
   3. メールアドレス認証
   4. 電話番号の認証（SMS認証）
   5. ドメイン認証
      - DNS TXTやHTMLタグ/ファイル\*\*で所有を証明
3. 閲覧権限の制御
   - 誰に、どのデータの閲覧権限を渡してもよいのか
   - 連携したすべてのアカウントや情報を、それぞれのクライアントごとに公開するか決められるようにしたい
4. ドメインは、`accounts.freeism.app`
   - 一旦は、freeism向けに提供したいため
5. データ移行を簡単にしたい
   - インポート、エクスポートを簡単にできるようにしたい
6. Fediverseに対応
   - DID, ActivityPub, ATProtocolに対応
7. OSSとしてすべてを公開
8. あらゆる一致文言に対応
   - APIリクエストで、URLやユーザーIDなどいろいろな形式にするけど、その場合にいろいろな正規表現や条件分岐をして、なんとか探し出す処理にしておく
9. OAuthクライアントの対応範囲を拡張
   - [v0.1](../v0.1/main.md)で対応するバックエンドを持つWebサービスに加えて、次のアプリからも連携できるようにする
     1. バックエンドを持たず、ブラウザだけで動くアプリ
     2. 利用者のPCで実行するCLI
10. 登録アプリの共同管理
    - 複数のAccountsユーザーが1つの登録アプリを共同管理できる
    - 各共同管理者は、自分のAccountsユーザーでログインして同じアプリを管理する
    - 共同管理者は全員が同じ権限を持ち、アプリ設定の変更、管理者の追加・削除、アプリ自体の削除を行える
    - 共同管理者の追加方法は、v0.3の要件整理で決定する
11. JSONアップロードによるWeb URLの一括登録・一括検証
    - 本人が複数の外部WebページのURLを含むJSONをアップロードし、URLの登録と所有権の検証をまとめて実行できる
    - 所有権の検証には、[v0.1のWebページ検証](../v0.1/main.md#webページの検証仕様)を適用し、各外部ページに設置された本人のAccounts公開プロフィールへのリンクを確認する
    - 検証に成功したURLは本人のAccountsユーザーへ紐付け、一般公開・OAuthクライアントへの提供には本人の公開設定を適用する
    - JSONの形式、一括処理の件数・容量上限、途中でエラーや検証回数の上限に達した場合の扱い、結果の表示方法は、v0.3の要件整理で決定する
    - 実装作業は[v0.3実装計画](../../implementation-plan/v0.3.md)に記載する
12. WebFinger、AT Protocol、
