## v0.3で追加する機能

1. メールアドレス認証
2. 電話番号の認証（SMS認証）
3. 文言一致の拡張
   - APIリクエストで、URLやユーザーIDなどいろいろな形式にするけど、その場合にいろいろな正規表現や条件分岐をして、なんとか探し出す処理にしておく
4. OAuthクライアントの対応範囲を拡張
   - [v0.1](../v0.1/main.md)で対応するバックエンドを持つWebサービスに加えて、次のアプリからも連携できるようにする
   1. バックエンドを持たず、ブラウザだけで動くアプリ
   2. 利用者のPCで実行するCLI
5. 登録アプリの共同管理
   - 複数のAccountsユーザーが1つの登録アプリを共同管理できる
   - 各共同管理者は、自分のAccountsユーザーでログインして同じアプリを管理する
   - 共同管理者は全員が同じ権限を持ち、アプリ設定の変更、管理者の追加・削除、アプリ自体の削除を行える
   - 共同管理者の追加方法は、v0.3の要件整理で決定する
6. JSONアップロードによるWeb URLの一括登録・一括検証
   - 本人が複数の外部WebページのURLを含むJSONをアップロードし、URLの登録と所有権の検証をまとめて実行できる
   - 所有権の検証には、[v0.1のWebページ検証](../v0.1/main.md#webページの検証仕様)を適用し、各外部ページに設置された本人のAccounts公開プロフィールへのリンクを確認する
   - 検証に成功したURLは本人のAccountsユーザーへ紐付け、一般公開・OAuthクライアントへの提供には本人の公開設定を適用する
   - JSONの形式、一括処理の件数・容量上限、途中でエラーや検証回数の上限に達した場合の扱い、結果の表示方法は、v0.3の要件整理で決定する
   - 実装作業は[v0.3実装計画](../../implementation-plan/v0.3.md)に記載する
7. PointsにDIDログインで入る実装にしない
   - 説明
     - Accounts経由で、アカウント情報を渡す
     - 検証アプリごとにAPIを提供してPointsへ提供する
     - その理由
       - PointsにAccountsの責務（アカウント統合）を漏らして、アカウント系の処理を入れるのは避けたい。
       - Pointsは、出来る限りシンプルなAPIを叩けば良いだけにしたい。
   - 要件
     1. 検証済みのデータをAT Protocolなどで共有することはしない
        - 説明
          - 検証済みのデータとして保存しなくて良い。ただ連携するリストを保持するだけで各編集アプリが検証の責務を負う
        - その設計にする理由
          - 正しい検証済みであることをAT Protocolなどに保存しているJSONで保証する仕組みを考えつかなかった
     2. Fediverseのみにしない
        - 説明
          1. 正本のコピーとして保存する
             - AT Protocol、Solid、ActivityPubなどは、Cloudflare D1のコピーとして保存する
          2. 非公開データとして保存する
             - AT Protocol SpacesとSolidには、Accounts内で指定した外部アカウントのみを非公開データとして入れる。
             - そこにアクセスできる誰でも見れる情報としては保存しない。
             - 全部のAccountsの外部アカウントの情報を非公開データとして入れないし、指定データは公開データとして入れない。
             - ユーザーが許可した他のAccounts系サービスのみが、そのデータにアクセスできて、かつ許可したデータのみ取得できる状態にしたい。なので基本は非公開で、アクセス権限を得たとしてもAccounts内で許可したデータのみ操作できるようにしたい
        - その設計にする理由
          1. 勉強不足
             - 本DBとして使用したいけど実装者の実力が及ばない&勉強の時間がないので、UXを損なわず提供することが難しいと判断して断念した。
