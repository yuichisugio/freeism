コンポーネント規則

OAuth 公開中 非公開 未検証 双方向リンク 未保存 2件 未保存の変更なし 本文中のリンク
Points：公開する外部アカウントが選択されていないため、Points に情報を提供しません。
  • ボタン: 1つの面に主ボタンは1つ。取り消せない操作は danger、外す操作は danger-soft。ログイン系はアイコン付きで、前回使用したサービスだけ主ボタン＋「前回使用」チップ。
  • リンク: 本文中のリンクは --link（ライトは主色より少し濃い青、ダークは明るい青）。下線はホバー時だけ。外部リンクはURL文字列のすぐ右に外部リンクのアイコンを置き、新しいタブで開く。
  • チップ: 状態を示すだけで押せない。成功・公開中は緑、未検証・非公開は灰、未保存は強調色。表の行と「詳細」には成功した検証方法だけを出し、失敗した試行のチップは出さない。未検証行の「詳細」は直近の検証結果の1行・案内文・「再検証」・「すべての連携解除」。検証方法名は「OAuth」「双方向リンク」「DNS TXT」。
  • 情報メッセージ: 表の下に info トーン（--accent-soft）で出す。保存済みの状態を基に、公開先ごとに証明済みの選択が0件なら表示する。エラーではないので danger を使わない。
  • 枠カード: 1つの設問・1つの機能に1枚。見出しは左上、操作は本文の下。
  • 表: 行と列の構造を崩さない。ラッパーで縦横スクロールし、見出し行と先頭列を固定する。スクロール連鎖は止めず、表の端に達したらページがスクロールする。行の上下余白は --space-4（640px 以下は --space-3）。先頭列は --col-lead（「GitHub：yamada-hanako」が1行に収まる幅）で固定し、長い名前は折り返す。公開先列は --col-dest。表はカードの幅いっぱいに広げ、画面が狭くなったら各列を最小幅（--col-lead・--col-dest）まで縮め、それでも収まらないときだけ横スクロールする。縦は画面の高さの90%までにする。未検証行もチェックでき、一括のチェックは全行が対象。列見出しの「公開中／非公開」と情報メッセージは、証明済み行のチェックだけで計算する（未検証だけがチェックされた列は「非公開」）。変更したセルは強調色で塗る。行の表示は「サービス名：識別子」。
  • 保存バー: 表の下に常に表示し、position: sticky; bottom で追従する。変更が0件のときは「未保存の変更なし」と表示し、「破棄」「公開設定を保存」を無効にする。
  • 狭い幅の表: 640px 以下（コンテナ幅）は同じ表を圧縮して表示する。先頭列はアイコン＋サービス名と識別子の2段（--col-lead-compact）、公開先列は短縮名で --col-dest-compact。行と一括の先頭列のチェック、成功した検証方法のチップは省き、「未検証」と「詳細」は残す。
  • 同意画面: OAuth クライアントから遷移したときは専用画面。ヘッダーはロゴと人アイコンのみでタブなし。「連携するアカウント」「紹介ページ」「戻り先」は、ラベルの下の行に値を置く。今回の連携先の列だけを選ばせ、選択リストの見出し行は「アカウント」と一括チェック。「同意しない」（ghost）と「同意して戻る」（primary）を置く。「公開設定を保存」は出さない。証明済み行のチェックが0件なら「同意して戻る」を無効にし、理由を出す。
  • 日時: 2026/09/12 14:03 (UTC) の形式。英語の画面も同じ形式。
  • サービスアイコン: 実装では https://www.google.com/s2/favicons?domain={host}&sz=64 を <img> で表示し、onerror で地球儀アイコンに差し替える。ファビコンは --favicon-plate の台に載せ、ダークでも見えるようにする。モックは取得済みの data URI を使い、hanako.dev は取得できない例として地球儀になる。
  • ダイアログ: 確認と入力は <dialog>。右下に「キャンセル」と実行ボタンを並べ、危険な操作は右端。退会は「DELETE」の入力が一致するまで実行ボタンを無効にする。未ログインでログインが必要な画面は、本文を1文にしてログインダイアログを開く。
  • インラインフォーム: 開発者向けの登録フォームは初期状態では閉じ、「新しいクライアントを登録」か一覧の「編集」を押したときだけ開く。「保存」の右に「キャンセル」（フォームを閉じ、入力は破棄）。項目タイトルの直下に「必須／任意」の印と説明文、その下に入力欄。複数値（リダイレクトURL）は1行1入力欄、行末に「削除」、下に「＋ 追加」。
  • ポップオーバー: ヘッダー右の人アイコン（アカウント切替）と、公開プロフィールの言語ドロップダウンは同じ見た目。右下に開き、外側クリックと Esc で閉じる。切替先のユーザーは行全体がボタンで、右端に矢印。

レイアウト規則

  • 最大幅: トップ・アカウント連携・その他は同じ --page-max。読み物の本文は --prose-max（約65文字）。
  • ヘッダー: ロゴ（Freeism Accounts）・タブ・右端の3列。未ログインは右端に何も置かない。同意画面はタブを置かない。640px 以下はタブを2段目に回して中央寄せし、はみ出す場合だけ横スクロール。
  • アカウント連携: 公開プロフィールURL → URLで証明 → ログインで証明 → 公開設定 → 表 → 情報メッセージ → 保存バーの縦1列（PC幅でも横に並べない）。保存バーは画面に1つ。640px 以下は全幅。
  • 同意画面: 中央の1枚カード（Google 風、幅 --consent-w）。見出し → 連携するアカウント → 紹介ページ・戻り先 → 利用目的 → 選択リスト → ボタンの順に上から読む。
  • レスポンシブ: 各画面は自身の幅で判定する（コンテナクエリ）。820px 以下で2列を1列にし、表は縮めずにスクロールする。
  • 使い方: Q&A アコーディオンを本体にし、PC幅は左に固定の目次、820px 以下は上部の折りたたみ目次。目次を押すと該当の話題へスクロールする。
  • 公開プロフィールの言語: 文言は言語ごとに分け、併記しない。実装では言語の切替を ?lang=en 付きの別URLへのリンクにし、URL単位のキャッシュと JavaScript 無しの閲覧を両立する。

実装が必要な新規操作

  • 行ごとの「再検証」: 現行は同じURLで「保存して検証する」を押す。
  • 検証方法ごとの「この証明を解除」: 現行は行全体の「連携解除」と「OAuthの認証連携だけ解除する」のみ。
  • 「詳細」の開閉: 現行は証明の一覧を常に表示する。
  • 専用の同意画面: 現行は「アカウント連携」画面の上部に同意パネルを出し、同じ画面の表で選ぶ。
  • テーマ設定: 現行は無い（ライト・ダーク・システム）。
  • DELETE 入力による退会確認: 現行はチェックボックス「内容を確認した」。
  • 言語ドロップダウン: 公開プロフィールは現行は日英併記。
