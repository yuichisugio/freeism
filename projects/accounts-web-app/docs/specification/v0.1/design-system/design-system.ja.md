## 1. 目的と適用範囲

Freeism Accounts の見た目と操作の規則を、トークン・コンポーネント・レイアウト・画面構成の単位で定める。

| 対象 | 実装 |
| --- | --- |
| 管理画面（トップ・アカウント連携・その他・使い方・法務ページ・同意画面） | `src/frontend`（React、HeroUI v3、Tailwind CSS 4） |
| 公開プロフィール | `src/backend/views/public-profile-page.tsx`（hono/jsx の静的 HTML、JavaScript なし） |

- 色・書体・角丸・間隔・寸法はすべてトークンで決め、コンポーネントは直接の値を持たない。
- 画面の文言は各機能の `messages.ts` に置く。本文書の文言は主要なものだけを示す。

## 2. トーン

- カード中心の柔らかいトーンにする。面（カード）を背景から浮かせ、1枚のカードに1つの機能を置く。
- 主色は青（`--accent`）、見出しは丸ゴシック（Zen Maru Gothic）、本文はゴシック（Noto Sans JP）とする。
- ボタン・チップ・タブは丸い（pill）形、カードとダイアログは大きめの角丸にする。
- 強調色（黄、`--highlight`）は「未保存」と「前回使用」だけに使い、注意を引く場面を絞る。
- ライト・ダークの両方を持ち、既定はシステムの設定に従う。

## 3. トークン

すべての寸法トークン（文字サイズ・間隔・角丸・アイコンと操作部品・レイアウトの寸法、Tailwind の `--spacing`）は、基準値 × `--scale`（1.1）とする（例: `--text-md: calc(14px * var(--scale))`）。
この章の px は基準値で、実効値はその 1.1 倍（例: `--text-md` は 14px → 15.4px）。公開プロフィールのインライン CSS も同じ倍率を掛ける。行間・`--prose-max`（`ch`）・`--table-max-h`・ブレークポイント・枠線の太さ・影には掛けない。

## 4. コンポーネント規則

### 4.1 ボタン

| 種別 | 見た目 | 使う場面 |
| --- | --- | --- |
| 主（primary） | `--accent` の面、`--accent-foreground` の文字 | 面ごとに1つの主操作（「検証する」「公開設定を保存」「同意して戻る」「保存」「取り込む」「再検証」「ログインする」） |
| セカンダリ（secondary） | `--surface` の面と `--border` の枠 | 並ぶ副操作（「未検証で保存」「コピー」「データ出力」「ファイルを選択」「この証明を解除」「キャンセル」（フォーム）、ログイン系） |
| ソフト（soft） | `--accent-soft` の面、`--accent` の文字 | 主色で目立たせたいが主操作ではない操作 |
| 補助（tertiary） | `--surface-secondary` の面 | ダイアログの「キャンセル」、「テンプレートをダウンロード」「AIに整形を頼む文面をコピー」「＋ 追加」 |
| ゴースト（ghost） | 透明、`--muted` の文字 | 表の行内操作（「編集」「削除」）、保存バーの「破棄」、「同意しない」、閉じる（×） |
| 危険（danger） | `--danger` の面 | 取り消せない操作の実行（確認ダイアログの実行ボタン、「退会する」、クライアント編集の「削除」） |
| 危険（淡）（danger-soft） | `--danger-soft` の面、`--danger` の文字 | 外す操作・危険な操作の入口（「すべての連携解除」、その他の「退会」） |

- 高さは通常 `--control-h`（左右 `--space-5`、`--text-md`）、小は `--control-h-sm`（左右 `--space-4`、`--text-sm`）とする。形は `--radius-pill`、文字は `--weight-medium` とする。
- 1つの面に主ボタンは1つにする。
- 無効のボタンは不透明度 .45 にし、`cursor: not-allowed` にする。
- ログインボタンはサービスのアイコン付きにする。前回使用したサービスだけ主ボタンにし、「前回使用」チップ（強調色）を付ける。

### 4.2 チップ

チップは状態を示すだけで押せない。

| 種別 | 見た目 | 使う場面 |
| --- | --- | --- |
| success | `--success-soft` / `--success` | 成功した検証方法（チェックのアイコン付き。「OAuth」「双方向リンク」「DNS TXT」）、「公開中」、「現在」、「成功」 |
| default | `--surface-secondary` / `--muted` | 「未検証」「非公開」、URL検証の「判断できませんでした」 |
| warning | `--warning-soft` / `--warning` | URL検証の「証拠を確認できませんでした」 |
| accent | `--accent-soft` / `--accent` | 使い方の「開発者向け」 |
| highlight | `--highlight` / `--highlight-foreground` | 「未保存 n件」「前回使用」 |

- 表の行と「詳細」には成功した検証方法だけを出し、失敗した試行のチップは出さない。
- 検証方法名は「OAuth」「双方向リンク」「DNS TXT」とする。

### 4.3 枠カード（設問カード）

- 1つの設問・1つの機能に1枚のカードを使う。
- カードは `--surface`、`--border` の枠、`--radius-xl`、`--shadow` とする。内側は上下 `--space-5`、左右 `--space-6`（640px 以下は `--space-4`）とする。
- 見出しは左上、操作は本文の下に置く。
- 「その他」の設問カードは、左列（`--q-label-w`）に見出し（`--text-lg`）と説明（`--text-xs`、`--muted`）、右列に操作を置く。640px 以下は1列にする。
- 退会のカードは枠を `--danger` 寄りにし、見出しを `--danger` にする。

### 4.4 表

表は「アカウント連携」の公開設定、開発者向けのクライアント一覧、OSSライセンスで使う。

- 行と列の構造を崩さない。表をラッパーで縦横スクロールし、見出し行と先頭列を `position: sticky` で固定する。
- スクロール連鎖は止めず、表の端に達したらページがスクロールする。
- 表は `--surface` のカードに入れ、縦は `--table-max-h` までにする。
- 列見出しは `--text-xs`、`--muted`、`--weight-regular` にする。

公開設定の表は次の規則に従う。

- 行は外部アカウント、列はプロフィールと各連携先（OAuth クライアント）とする。行の表示は「サービス名：識別子」とする。
- 表はカードの幅いっぱいに広げる。画面が狭くなったら先頭列を `--col-lead`、公開先列を `--col-dest` まで縮め、それでも収まらないときだけ横スクロールする。
- 先頭列は `--col-lead` で固定し、長い名前は折り返す。
- 行の上下余白は `--space-4`（640px 以下は `--space-3`）とする。
- 見出し行の各列に、公開先名と「公開中」（success）／「非公開」（default）のチップを置く。
- 見出し行の下に一括行（`--surface-secondary`）を置く。先頭列の一括チェックは全行×全列、各列の一括チェックはその列の全行が対象で、未検証行も含む。
- 各行の先頭列にはその行の一括チェック、サービスアイコン、「サービス名：識別子」、検証方法のチップ（未検証は「未検証」）、「詳細」の開閉ボタンを置く。
- 一括チェックは全選択で ON、一部選択で中間表示、対象が無ければ無効にする。
- 未検証行もチェックできる。チェックは「その公開先に出す候補」を意味し、公開されるのは証明済みの行だけとする。
- 列見出しの「公開中／非公開」は、保存済みの状態で、証明済み行のチェックが1件以上あれば「公開中」とする。未検証の行だけがチェックされた列は「非公開」とする。
- 保存済みから変更したセルは `--highlight` で塗る。
- 「詳細」を開くと、行の下に全幅の詳細行（`--surface-secondary`）を出す。詳細の中身はスクロール領域の幅に合わせて左端に固定する。
- 証明済み行の詳細は、成功した検証方法ごとに枠（`--radius-lg`）を並べる。枠には方法名と「成功」チップ、証明日時・証拠・識別子、「この証明を解除」を置く。下端に「すべての連携解除」を置く。
- 証拠の項目名は OAuth が「証拠」、双方向リンクが「証拠を確認したページ」、DNS TXT が「TXTレコード名」とする。
- 未検証行の詳細は、直近の検証結果の1行（「直近の検証 {日時}：{結果}」）、案内文、「再検証」、「すべての連携解除」とする。

640px 以下（狭い幅）は同じ表を圧縮して表示する。

- 先頭列はアイコン＋サービス名と識別子（`--font-mono`、`--text-xs`）の2段にし、幅を `--col-lead-compact` にする。
- 公開先列は短縮名（`--text-2xs`）にし、幅を `--col-dest-compact` にする。
- 行と一括行の先頭列のチェック、成功した検証方法のチップは省く。一括行の先頭列は「一括」と表示する。
- 「未検証」と「詳細」は残す。

### 4.5 情報メッセージ

- 表の下に info トーン（`--accent-soft` の面、`--accent` の情報アイコン、`--radius-md`）で出す。エラーではないので danger を使わない。
- 「アカウント連携」では、保存済みの状態を基に、公開先ごとに証明済みの選択が0件なら表示する。
  - プロフィールの列は「プロフィール：公開する外部アカウントが選択されていないため、公開プロフィールは表示されません。」と表示する。
  - 連携先の列は「{連携先}：公開する外部アカウントが選択されていないため、{連携先} に情報を提供しません。」と表示する。
- 同意画面では、選択中の状態で証明済みの選択が0件なら「{連携先}：公開する外部アカウントが選択されていないため、同意できません。証明済みのアカウントを1件以上選択してください。」を表示する。

### 4.6 エラー通知とURL検証の結果

- エラー通知は `--danger-soft` の面（`--radius-md`）にし、見出しを `--danger` の太字、項目は箇条書き、補足は `--text-xs` の `--muted` にする。`role="alert"` を付ける。
- URL検証の結果は `--surface` の枠（`--radius-lg`）にし、太字の要約、検証方法ごとのチップ（「{方法}: {結果}」）と案内文、証拠のページを並べる。`role="status"` を付ける。

### 4.7 保存バー

- 保存の送信中は、その画面の入力（表のチェック、フォームの入力欄、一覧の「編集」「削除」、同意画面の選択）を無効にし、送信した内容と同じときだけ完了時に下書きを消す。
- 「アカウント連携」の保存バーは表と情報メッセージの下に常に表示し、`position: sticky; bottom: var(--space-4)` で追従する。
- 見た目は `--surface`、`--border` の枠、`--radius-pill`、`--shadow-pop` とし、右寄せにする。640px 以下は全幅にして `--radius-xl` にする。
- 左に状態、右に「破棄」（ghost、小）と「公開設定を保存」（primary、小）を置く。狭い幅でも折り返さず1行に並べ、640px 未満は状態を `--text-xs`、間隔を `--space-1`、バーの左の余白とボタンの左右の余白を `--space-3` にして、360px 幅でも「未保存の変更なし」「未保存 n件」を省略せずに収める。
- 全幅のときも中身は右に寄せ、状態と「破棄」の間隔を「破棄」と「公開設定を保存」の間隔と同じにする。余った幅はバーの左に回す。
- 変更が0件のときは「未保存の変更なし」（`--muted`）と表示し、「破棄」「公開設定を保存」を無効にする。1件以上のときは「未保存 n件」チップ（highlight）を表示する。
- 保存バーは画面に1つにする。
- 「その他」の表示名は、未保存の変更があるときだけ同じ形の保存バー（「破棄」「保存」）を出す。表示名が不正なときは「保存」を無効にする。言語とテーマは選んだ時点で反映し、保存バーの対象にしない。

### 4.8 ダイアログ

- 確認と入力は `<dialog>` 相当のモーダルにする。幅は `--dialog-w`、角丸は `--radius-2xl`、影は `--shadow-pop`、背面は `--backdrop` とする。どの幅でも画面の中央に表示する。
- 閉じるボタン（×）は、見出しと同じ行の右端に ghost の icon-only（小）で置く。
- 見出しは `--text-xl` にし、確認ダイアログは見出しの左に注意アイコンを置く。アイコンは危険なら `--danger`、注意なら `--warning` にする。
- 右下に「キャンセル」（tertiary、小）と実行ボタン（danger、小）を並べ、危険な操作は右端に置く。
- 背面のクリックと Esc で閉じる。
- 退会は「確認のため「DELETE」と入力」の欄（`--font-mono`）を置き、入力が「DELETE」と一致するまで「退会する」を無効にする。閉じたら入力を空に戻す。
- 未ログインでログインが必要な画面は、本文をログインを求めるカード（[6.7](#67-アカウント連携未ログイン)）にする。ログインダイアログは自動で開かず、「ログインする」で開く。ログインに失敗して `?error=` 付きで戻されたときだけ、失敗の案内とともに自動で開く。

| 確認 | 見出し | 実行 | キャンセル | トーン |
| --- | --- | --- | --- | --- |
| すべての連携解除 | 外部アカウントの連携を解除しますか？ | 解除する | キャンセル | danger |
| この証明を解除 | この証明を解除しますか？ | 解除する | キャンセル | danger |
| クライアントの削除 | このクライアントを削除しますか？ | 削除 | キャンセル | danger |
| 未保存の変更 | 保存していない変更があります | 変更を破棄して移動 | 編集に戻る | warning |
| 退会 | 退会しますか？ | 退会する | キャンセル | danger |

### 4.9 ポップオーバー

- ヘッダー右の人アイコン（アカウント切替）と、公開プロフィールの言語ドロップダウンは同じ見た目にする。
- 見た目は `--surface`、`--border` の枠、`--radius-xl`、`--shadow-pop`、内側 `--space-2` とする。幅はアカウント切替が `--menu-w`（640px 以下は画面幅から `--space-8` を引いた幅）、言語が `--lang-menu-w` とする。
- 起点の右下に開き、外側のクリックと Esc で閉じる。
- 開いている間、起点のボタンは `--accent-soft` の面、`--accent` の文字と枠にする。
- メニュー項目は `--radius-lg` の角丸にし、ホバーで `--surface-secondary` にする。

アカウント切替メニューは次の順に置く。

1. 現在のユーザーの行（`--surface-secondary`）。表示名（太字）、ユーザーID（`--font-mono`）、「現在」チップ。ユーザーの行にはアバターを置かない。
2. このブラウザーでログイン中のほかのユーザー。行全体をボタンにし、右端に矢印を置く。
3. 「アカウントを追加」（ログインダイアログを開く）。
4. 区切り線。
5. 「「{表示名}」からログアウト」の項目。

その場での切替（ユーザーIDの無い画面）とログアウトに失敗したときは、ヘッダーの行に並べず、人アイコンの下にエラー通知を重ねる。

言語ドロップダウンは、地球儀のアイコン・現在の言語名・キャレットの丸ボタンを起点にし、選択中の言語にチェックを付ける。

### 4.10 入力欄とインラインフォーム

- 入力欄は高さ `--input-h`、`--surface-secondary` の面、枠なし、`--radius-lg` とする。フォーカスで枠を `--accent`、面を `--surface` にする。不正な値は枠を `--danger` にする。
- URL・ID・公開鍵の入力欄は `--font-mono`（`--text-sm`）にする。
- 文字数の上限がある欄は右に「n / 上限」を置き、超えたら `--danger` にする。
- 開発者向けの登録フォームは初期状態では閉じ、「新しいクライアントを登録」か一覧の「編集」を押したときだけ開く。編集中の行は `--accent-soft` にする。
- 項目タイトルの右に「必須」（`--danger-soft` / `--danger`）か「任意」（`--surface-secondary` / `--muted`）の印を置き、直下に説明文、その下に入力欄を置く。
- 複数値（リダイレクトURL）は1行1入力欄にし、行末に「削除」、下に「＋ 追加」を置く。1行だけのときは「削除」を無効にする。
- 「保存」の右に「キャンセル」を置く。「キャンセル」はフォームを閉じ、入力を破棄する。編集時だけ右端に「削除」（danger）を置く。
- 未保存の入力があるときに別のクライアントを開くと、未保存の変更の確認ダイアログを出す。

### 4.11 選択肢の切替（分割ボタン）

- 言語とテーマの選択は、`--surface` の面と `--border` の枠の中に選択肢を並べ、選択中を `--accent` の面にする。
- ヘッダーのタブは `--surface` の面と `--border` の枠の中にリンクを並べ、現在の画面を `--accent-soft` の面、`--accent` の文字にする。

### 4.12 サービスアイコン（favicon）

- OAuth Provider（Google・GitHub・ORCID）の行は、ログインボタンと同じブランドのアイコンを 20px で表示する。Google のファビコン配信は ORCID にも 16px の画像を返すため、OAuth Provider には配信を使わない。
- URL の行は `https://www.google.com/s2/favicons?domain={host}&sz=64` を `<img>` で 20px に表示する。
- 取得できないホストには、配信が HTTP 404 で 16px の既定画像を返す。ブラウザーは 404 の画像も表示して `onerror` が起きないため、読み込み後の実寸（`naturalWidth`）が 16px 以下なら地球儀アイコン（`--favicon-fallback`）に差し替える。読み込み自体に失敗したとき（`onerror`）も同じにする。
- 公開プロフィールは JavaScript を使わないため、ブランドのアイコンはページ内の `<symbol>` で持ち、ファビコンは配信の画像をそのまま表示する（未知のホストは配信の既定画像になる。読み込みに失敗したときは背後の地球儀が見える）。
- アイコンは `--favicon-plate` の台（36px、`--radius-md`、`--border` の枠）に載せ、ダークでも見えるようにする。

### 4.13 リンク

- 本文中のリンクは `--link` にする。下線はホバー時だけ付ける。
- 外部リンクはURL文字列のすぐ右に外部リンクのアイコンを置き、新しいタブで開く。スクリーンリーダー向けに「（新しいタブで開く）」を添える。
- 画面タイトルの右に「使い方」への丸いリンク（ヘルプのアイコン付き）を置く。

### 4.14 日時

- 日時は `YYYY/MM/DD HH:MM (UTC)` の形式で表示する（例: `2026/09/12 14:03 (UTC)`）。
- 英語の画面も同じ形式にする。

### 4.15 トースト

- 保存・コピーなどの完了は、画面下中央のトーストで知らせ、3秒後に消す。
- 見た目は `--foreground` の面、`--background` の文字、`--radius-pill`、`--shadow-pop` とし、`role="status"` を付ける。

### 4.16 フォーカスと動き

- フォーカスは `:focus-visible` で `2px solid var(--focus)`、外側 2px に輪郭を出す。
- 開閉のキャレットは 180° 回転（.15s）させる。`prefers-reduced-motion: reduce` では動きを止める。

## 5. レイアウト規則

### 5.1 ヘッダー

- ロゴ・タブ・右端の3列にする。
  - ロゴ: ロゴマークと「Freeism Accounts」（`--font-display`、`--text-lg`、太字）。トップへのリンク。現在のページの印はタブだけに付け、ロゴには付けない。
  - タブ: 「トップ」「アカウント連携」「その他」の3つ。中央に置く。
  - 右端: 人アイコンの丸ボタン（`--control-h`）。押すとアカウント切替メニューを開く。未ログインは右端に何も置かない。
- 640px 以下はロゴと人アイコンを1段目に置き、タブを2段目に回して中央寄せする。はみ出す場合だけタブを横スクロールする。
- 同意画面はタブを置かない。

### 5.2 フッター

- 「使い方」「OSSライセンス」「プライバシーポリシー」「利用規約」の4リンクを中央に並べる（`--text-xs`、`--muted`）。
- 現在の画面のリンクは `--foreground` の `--weight-medium` にする。
- 同意画面と公開プロフィールにはフッターを置かない。

### 5.3 ページ

- トップ・アカウント連携・その他・使い方・法務ページは同じ `--page-max` にする。内側は上 `--space-4`、左右 `--space-6`、下 `--space-10` とし、要素の間隔は `--space-6` とする。
- 使い方の読み物の本文は `--prose-max`（約65文字）にする。
- 画面タイトル（`--text-2xl`）の右に「使い方」への丸いリンクを置く。
- 「アカウント連携」は、公開プロフィールURL → URLで証明 → ログインで証明 → 公開設定（節見出し） → 表 → 情報メッセージ → 保存バーの縦1列にする。PC幅でも横に並べない。

### 5.4 同意画面

- OAuth クライアントから遷移したときの専用画面にする。ヘッダーはロゴと人アイコンだけにする。
- 中央に1枚のカード（幅 `--consent-w`）を置く。
- 見出し → 連携するアカウント → 紹介ページ・戻り先 → 利用目的 → 選択リスト → 情報メッセージ → ボタンの順に上から読む。
- 「連携するアカウント」「紹介ページ」「戻り先」は、ラベル（`--muted`）の下の行に値を置く。
- 選択リストは今回の連携先の列だけを選ばせる。見出し行は「アカウント」と一括チェック、各行はアイコン・「サービス名：識別子」・チップ・右端のチェックとする。
- 「同意しない」（ghost）と「同意して戻る」（primary）を右寄せで置く。「公開設定を保存」は出さない。
- 証明済み行のチェックが0件なら「同意して戻る」を無効にし、情報メッセージで理由を示す。

### 5.5 公開プロフィール

- ヘッダーは `--surface` の帯（下に `--border`）にし、左にロゴ、右に言語ドロップダウンを置く。
- 本文は最大 640px の1列にし、表示名（`--text-2xl`）とユーザーID（`--font-mono`、`--text-xs`、`--muted`）、「証明済みのアカウント」の見出し、カードの一覧を置く。
- カードは、サービスアイコン、「サービス名：識別子」（外部アカウントのURLへのリンク、`rel="me"`、新しいタブで開く）、証明方法（「・」で連結）、証明日時を並べる。
- Webフォントは読み込まず、見出しとロゴは端末にある `--font-display` の書体を使う。
- 公開する外部アカウントが無いときは「このプロフィールは存在しません」を中央に表示する。
- 文言は言語ごとに分け、併記しない。言語の切替は `?lang=en` 付きの別URLへのリンクにし、URL単位のキャッシュと JavaScript 無しの閲覧を両立する。

| 見出し | 証明済みのアカウント | Verified external accounts |
| 証明方法 | 証明方法 | Method |
| 証明日時 | 証明日時 | Verified |
| 方法名 | OAuth・双方向リンク・DNS TXT | OAuth, Two-way link, DNS TXT |
| 区切り | 「：」 | 「: 」 |

### 5.6 使い方

- Q&A のアコーディオンを本体にする。
- PC幅は左に目次（`--q-label-w`、`position: sticky; top: var(--sticky-offset)`）、右に本文を置く。820px 以下は目次を本文の上の折りたたみにする。
- 目次を押すと該当の話題へスクロールし、折りたたみの目次は閉じる。
- 本文の先頭に「絞り込み」の検索欄（例: 「DNS、退会、リダイレクト」）を置く。入力に一致する質問だけを開いて表示し、該当が無ければ「該当する項目はありません。」を表示する。
- 開発者向けの話題は見出しに「開発者向け」チップを付ける。

### 5.7 ログインダイアログ

- 見出し「Freeism Accounts にログイン」と閉じるボタン（×）を置く。
- 「Googleでログイン」「GitHubでログイン」「ORCIDでログイン」を幅 `--provider-w` で縦に中央へ並べる。
- 下に「ログインすると、利用規約とプライバシーポリシーに同意したものとします。」（`--text-xs`、中央）を置く。

### 7.2 `styles.css` の構成

`styles.css` に次の順で置く。

1. `@import "tailwindcss";` と `@import "@heroui/styles";`。
2. `@theme`: 書体（`--font-display`、`--font-sans`、`--font-mono`）、文字サイズ（[7.5](#75-tailwind-の名前空間との対応)）、角丸。
3. `@theme inline`: HeroUI に無い色（`--color-border-strong`、`--color-highlight`、`--color-highlight-foreground`、`--color-favicon-plate`、`--color-favicon-fallback`、`--color-brand-github`）。
4. レイヤーに入れないトークン: `:root`（ライト）、`@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { … } }`、`:root[data-theme="dark"]` の3ブロック。値は [3](#3-トークン) の表と同じにする。
5. `:root` に HeroUI の変数とトークンの対応（[7.3](#73-heroui-の変数との対応)）。
6. `@layer base`: `body` の書体・サイズ・行間、見出し、リンク、`:focus-visible`。
7. `@layer components`: HeroUI の部品の見た目の調整（[7.6](#76-heroui-の部品の対応)）。

- HeroUI の変数はレイヤー（`theme`）の中で定義されるため、レイヤーに入れないトークンのブロックが詳細度に関係なく優先される。ダークの値も自前のブロックで必ず定義する。
- 対応（5）は `var()` の参照なので `:root` に1回書けばよい。テーマの切替で参照先のトークンが変わると追従する。

### 7.4 ダークモードの切替

- テーマは `<html>` の `data-theme` 属性で切り替える。「ライト」は `data-theme="light"`、「ダーク」は `data-theme="dark"`、「システム」は属性なしにする。
- 選んだテーマは言語と同じく localStorage（キー `accounts.theme`）に保存する。
- 描画前に適用するため、`RootDocument` の `<head>` に保存値を読んで `data-theme` を付けるインラインのスクリプトを置き、`<html>` に `suppressHydrationWarning` を付ける。
- 色の切替はトークンだけで行い、Tailwind の `dark:` 変種は使わない。HeroUI の `dark` 変種はシステムがダークなら `data-theme="light"` のときも当たるため、「ライト」の選択と食い違う。
- `color-scheme` はトークンのブロックごとに `light` / `dark` を指定し、スクロールバーやフォーム部品の既定色を合わせる。

| 確認ダイアログ（[4.8](#48-ダイアログ)） | `AlertDialog` | 幅 `--dialog-w`、角丸 `--radius-2xl`、内側 `--space-6` |
| ログインダイアログ・退会ダイアログ | `Modal` | 同上 |
| アカウント切替メニュー（[4.9](#49-ポップオーバー)） | `Dropdown` | 幅 `--menu-w`、角丸 `--radius-xl`、項目の角丸 `--radius-lg` |
| 入力欄（[4.10](#410-入力欄とインラインフォーム)） | `TextField`・`Input`・`TextArea` | 高さ `--input-h`、フォーカスで枠 `--accent`・面 `--surface` |
| 分割ボタン（[4.11](#411-選択肢の切替分割ボタン)） | `RadioGroup` | 1つを選ぶ設定の意味を保ち、見た目を分割ボタンに合わせる |
| 使い方のアコーディオン（[5.6](#56-使い方)） | `Accordion` | 項目を `--surface` の枠（`--radius-lg`）にする |
| トースト（[4.15](#415-トースト)） | `Toast` | `--foreground` の面、`rounded-full` |
| リンク | `Link` | `--link`、ホバー時だけ下線 |

- アイコンはモックの SVG（ロゴ・人・ヘルプ・チェック・注意・情報・キャレット・矢印・外部リンク・コピー・追加・アップロード・ダウンロード・ログアウト・閉じる・地球儀・GitHub・Google・ORCID）を React の部品にして `app-shell` に置く。色は `currentColor` かトークンを使う。
- ヘッダーの `max-w-6xl` や `border-default` などの直接の値は、トークンのユーティリティ（`max-w-(--page-max)` など）に置き換える。

### 7.7 書体の読み込み

- `__root.tsx` の `head` の `links` に Google Fonts の `preconnect` とスタイルシート（[3.2](#32-タイポグラフィ) のウェイト、`display=swap`）を追加する。
- 公開プロフィールは CSP（`default-src 'none'`）のため Web フォントを読み込まず、端末にある書体名の指定だけにする（[5.5](#55-公開プロフィール)）。

### 7.8 公開プロフィールの HTML

- 公開プロフィールは JavaScript を使わない静的 HTML のため、Tailwind のビルド結果を使わず、`Document` のインラインの `<style>` にトークンと必要な規則だけを書く。
- テーマの設定は閲覧者のシステムに従い、`:root` と `@media (prefers-color-scheme: dark)` の2ブロックにする。値は [3.1](#31-配色) の表と同じにする。
- 言語は `?lang=en` の有無で決め、`<html lang>` を合わせる。言語ドロップダウンは `<details>` と各言語へのリンクで作る。
- 日時は [4.14](#414-日時) の形式にする。

### 7.9 日時の表示

- `YYYY/MM/DD HH:MM (UTC)` の整形は、管理画面と公開プロフィールで共有するため `src/shared/format-date-time.ts` の `formatUtcDateTime` に置く。
