# Web App v0.2 Cross-App Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 未リリースの旧 `projects/web-app` を後方互換・データ移行なしで廃止し、`points.freeism.app` と `markets.freeism.app` を独立した Cloudflare Workers アプリとして構築し、`main` push だけで staging 検証から production まで直列デプロイできる状態へ移行する。

**Architecture:** `projects/points-web-app` と `projects/markets-web-app` は、それぞれ TanStack Start の静的 SPA shell + 4固定route prerender、Hono Worker、Workers Static Assets、D1 を持つ独立アプリとする。Points–Markets 間は Service Binding を transport に使うが、OAuth bearer token を必須とし、Points 所有の OpenAPI から生成した型/Client だけを契約境界にする。Worker/binding/named environment/custom-domain route は Wrangler/Vite plugin、DNS/apex redirect/Access/WAF/rate-limit は Terraform が所有し、同じ Cloudflare resource を二重管理しない。

**Tech Stack:** Node `24.18.0`、pnpm `10.33.3`、Vite Plus `0.2.4`、TanStack Start `1.168.27`、React `19.2.7`、Hono `4.12.29`、Drizzle ORM `0.45.2`、D1、Better Auth、Workers Static Assets、Durable Objects、Workflows、OpenAPI、Terraform `1.15.7` / Cloudflare Provider `5.21.1`、GitHub Actions。

Decision Registerで`承認対象`の行は、仕様案としてdocsに保持しても実装入力にはしない。該当DECが利用者の承認により`採用`へ変わるまで、その値に依存する子Taskだけを開始せず、別の値を実装者判断で補わない。

現時点の承認gateはDEC-243、DEC-252、DEC-254、DEC-256〜DEC-261である。Points子計画は再所有、Package、代用／自動分配、CSV export、account close／reopenの対応Taskを、Markets子計画はretry budget、listing／review境界、Package contractの対応Taskを停止する。新しい`承認対象`を追加した場合もこの列挙を待たず同じ一般規則を適用する。

この計画では次を不変条件として扱う。

- 後方互換、旧 URL/API/schema/session fallback、旧データ移行を実装しない。
- Task/Group/一般 member/notification/PWA/image upload/Next.js/Auth.js/Prisma/Supabase/Upstash/SSE を新実装へ持ち込まない。
- Points と Markets は別 Better Auth、別 host-only Cookie、別 D1、別 user ID、別 session を持つ。
- Points の Google/GitHub は login と explicit link の双方に同じ Provider 集合を使う。Provider 単位の link-only 独自 hook は作らない。
- Better Auth のメール一致 implicit link は禁止し、本人は `providerId + accountId` で識別する。
- Service Binding は認可根拠ではない。Points Resource API は token class/grant/scope/audience/client を常に検証する。
- runtime SSR、TanStack server functions、Next Server Actions を使わない。
- SPA shell は `/index.html`。Cloudflare の汎用 `not_found_handling: "single-page-application"` は使わない。
- `/` は shell hydrate後に描画するSPA topで、top本体のSSGとは扱わない。SSGは`/terms`、`/privacy`、`/help`、`/docs`だけを`*.html`へ明示生成し、自動discovery／crawlを無効にする。
- 4固定routeはlocale別URL／query／HTMLへ分けず、各HTMLに日本語正本と英語参照訳の双方を静的renderする。JavaScript無効時は両言語を読め、JavaScript有効時は保存済み選択→browser言語→日本語の順で表示言語を決める。
- 日本語正本を機械翻訳または英語側から自動更新しない。英語参照訳はproduction release前のbilingual reviewとlocale別content hash一致を必須gateにする。
- Static Assets は asset-first、`not_found_handling: "none"`、`html_handling: "auto-trailing-slash"`。`assets_navigation_has_no_effect`を明示し、asset miss 後に Worker が GET/HEAD の HTML navigation だけ Asset Bindingのcanonical `/`からshellを返す。存在しない API/JS/CSS/image は 404 にする。
- `CLOUDFLARE_ENV=staging|production` は build 時に選択し、生成された flattened Wrangler config を直後に deploy する。build 済み artifact を `wrangler deploy --env` だけで切り替えない。
- `main` push 以外に production trigger、`workflow_dispatch`、手動 environment approval を置かない。
- 状態変更 workflow は `cancel-in-progress: false` で直列化する。
- Better Auth `1.7.0-rc.1` は開発/staging 限定。最初の production は Better Auth `1.7.0` 正式版への exact bump と全認証回帰成功まで進めない。

## 3. Cross-app interfaces

### 3.1 Workspace/package interface

両 app の package 名は次で固定する。

- `@freeism/points-web-app`
- `@freeism/markets-web-app`

子計画完了時に両 package は次の script 名を同じ意味で提供する。

| Script                  | Contract                                                          |
| ----------------------- | ----------------------------------------------------------------- |
| `check`                 | format/lint/typecheck を副作用なしで実行                          |
| `test`                  | React/domain unit/property test                                   |
| `test:worker`           | Workers Vitest integration                                        |
| `test:e2e`              | Playwright browser E2E。固定ページのJS無効／keyboard／ARIAも含む  |
| `build:staging`         | `CLOUDFLARE_ENV=staging` を build 前に設定                        |
| `build:production`      | `CLOUDFLARE_ENV=production` を build 前に設定                     |
| `build:assert`          | flattened config、environment、shellと4固定HTMLを検証             |
| `db:migrate:staging`    | named staging D1 に forward migration を適用                      |
| `db:migrate:production` | bookmark 記録後に production D1 migration を適用                  |
| `deploy:staging`        | staging build artifact の直後に generated config を deploy        |
| `deploy:production`     | production build artifact の直後に generated config を deploy     |
| `smoke:staging`         | custom domain/TLS/assets/API/auth/reconciliation の staging smoke |
| `smoke:production`      | read-only/低リスクの production smoke                             |

`deploy:*` は別 environment の既存 build artifact を再利用しない。D1/DO/Workflow 固有処理は子計画で実装する。

### 3.2 Worker/static interface

- logical Worker base: `points-worker` / `auction-worker`
- named environment deployment: `*-staging` / `*-production`
- domain: `staging.points.freeism.app`、`staging.markets.freeism.app`、`points.freeism.app`、`markets.freeism.app`
- Worker first paths: `/api/*`、`/.well-known/*`
- Static Assets binding: `ASSETS: Fetcher`
- SPA shell: `/index.html`
- fixed prerender assets: `/terms.html`、`/privacy.html`、`/help.html`、`/docs.html`
- fixed-page locale contract: 4 HTMLそれぞれが`lang="ja"`と`lang="en"`の全contentを含み、localeによるpath／query／cache key分岐を持たない
- API health: `GET /api/health`
- API 404: RFC 9457 Problem Details JSON。HTML を返さない

### 3.3 Points–Markets contract interface

Canonical OpenAPI は `docs/web-app/v0.2/points-markets.openapi.json` とし、operationId を次で固定する。

- `projects/points-web-app/src/generated/points-markets-api.ts`

### 3.4 Environment/binding ownership

| Resource                                                                                                          | Owner                                                                 |
| ----------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Worker、Static Assets、D1 binding、DO migration/namespace、Workflow binding、Service Binding、custom-domain route | app ごとの `wrangler.jsonc` + Vite plugin                             |
| apex/www DNS、apex/www redirect、staging Access、managed/custom WAF、edge IP rate-limit、Turnstile widget         | Terraform                                                             |
| app/user/resource 単位の正確な rate-limit、idempotency、authorization                                             | Hono/D1/DO。子計画                                                    |
| OAuth provider/client secret、Better Auth secret、token encryption key                                            | environment 別 Worker Secret。repository/Terraform state に保存しない |
| Terraform state                                                                                                   | 新規専用 R2 bucket。旧画像 R2 と別 resource                           |
